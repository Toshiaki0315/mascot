# 省電力の検討メモ

バッテリー駆動のときに、電力の消費を減らす方法を調べた記録です（2026-10-25）。
**「省電力モード」は、今回は実装しないことにしました。** あとで取り組むときに、調べ直さなくて済むよう、わかったことと判断をここに残します。

## 結論

- 実装したもの：**画面を誰も見ていない間（画面ロック・ディスプレイ消灯・別ユーザーへの切り替え）は、動きを止める**（v0.7.10）。
- 実装していないもの：下の「候補の一覧と費用対効果」の、ほかの項目すべてと、省電力モードそのもの（電源の状態による切り替えと設定）。
- 見送った理由：まずは、見た目を変えずに済む、画面を見ていない間の停止だけを入れ、ほかは必要になってから考える、という判断です。

## 実装したもの：画面を見ていない間の停止

次のどれかに当てはまる間は、マスコットの動きなどを止めます。

| 状態 | 見つけ方（`src-tauri/src/system.rs`） |
| --- | --- |
| ディスプレイが消えている | `CGDisplayIsAsleep(CGMainDisplayID())` |
| 画面がロックされている | `CGSessionCopyCurrentDictionary()` の `CGSSessionScreenIsLocked` |
| 別のユーザーに切り替わっている | 同じ辞書の `kCGSSessionOnConsoleKey` が false |

- 状態は 2 秒ごとに見ます（`lib.rs` の `spawn_screen_watcher`）。いずれの API も、権限（画面収録やアクセシビリティ）は要りません。
- 状態は `Shared.paused` に置き、各スレッドが見ます。

| 処理 | 止まっている間 |
| --- | --- |
| マスコットの動き（`wander.rs`） | 計算せず、1 秒に 1 回、確認するだけ |
| カーソルの監視（`lib.rs`） | 止める |
| メニューバーの文字の更新（`status.rs`） | 止める |
| ふきだしの追いかけ（`bubble.rs`） | 止める（1 秒に 1 回、確認するだけ） |
| リマインダー・タイマー・ポモドーロの時刻チェック（`reminder.rs`） | 0.5 秒から 2 秒ごとに粗くする（時刻は守る） |

- 戻ったときは、`reset` と `resync` を立てて、歩き方を計算し直します（止まっていた間の時間で、マスコットが飛ばないようにするため）。
- 実機の状態の読み取りは、テストで呼べること（クラッシュしないこと）を確かめています。実際に画面をロックして止まる様子までは、自動のテストでは確かめていません。

## 調べたこと：電力を使っている処理

### 測った値（2026-10-25、`tauri dev` の開発用ビルド、バッテリー駆動、操作中、歩いている最中）

| 項目 | 値 |
| --- | --- |
| CPU 使用率 | 約 9〜16% |
| 待ち状態からの起床（`top` の `idlew`） | 毎秒 約 50〜60 回（6 秒で 370 回と 311 回） |

- 開発用ビルドは最適化がないので、配布版より重く出ます。ただ、起床の回数は、コードの作り（間隔）でほぼ決まります。
- 起床が多いほど、電池を使います。ウィンドウを動かす処理は、画面合成（WindowServer）も動かすので、特に響きます。
- `sample` で見ると、アプリのプロセスは、ほとんどの時間を待ち状態で過ごしていました。重いのは、回数と、画面を動かす処理でした。

### 処理の一覧（コードの間隔から見積もった値）

| 処理 | 間隔 | 毎秒の起床（見積もり） |
| --- | --- | --- |
| 歩く動き（ウィンドウを動かす）`wander.rs` の `WALK_TICK` | 33ms（約 30fps） | 約 30 |
| 飛ぶ・ドラッグ `FAST_TICK` | 16ms（約 60fps） | 約 60（操作中だけ） |
| じっとしているときの動きの計算 `IDLE_TICK` | 100ms | 約 10 |
| 眠る・起きる、休憩の声かけの確認 `SLEEP_CHECK` | 250ms | 約 4 |
| カーソル位置の監視 `lib.rs` | 近い 30ms／遠い 150ms | 7〜33 |
| 画面の抜き差し・全画面の確認 `WINDOW_CHECK` | 1 秒（窓の上では 250ms） | 1〜4 |
| 時刻チェック `reminder.rs` | 500ms | 2 |
| メニューバーの文字の更新 `status.rs` | 1 秒 | 1 |
| ふきだしの追いかけ `bubble.rs` | 出している間 33ms／出していない間 250ms | 4〜30 |
| 画面側のアニメーション（跳ね 1.2 秒・まばたき 4 秒） | — | 約 1（描画プロセス側） |
| 時報の確認・設定の見比べ・天気 | 20 秒〜10 分 | 0.1 以下 |

- 眠って（入力が 60 秒ない）いる間も、毎秒おおよそ 20 回起きています。眠っているアプリは、本来、毎秒 1 回程度まで減らせます。
- 特に大きいのは、**歩く動き、カーソルの監視、じっとしているときの細かい計算**です。

## 候補の一覧と費用対効果

「手間」は、作業量と、ほかの動作を壊すリスクの目安です。効果は見積もりで、測った値ではありません。

| 順位 | 内容 | 効果の見込み | 手間 | 見た目・操作への影響 |
| --- | --- | --- | --- | --- |
| 1 | **眠っている間の間引き**：動きの計算を 100ms から 500ms へ。カーソル監視を 150ms から 1 秒へ | 眠っている間、毎秒 約 15 回減。画面を見ている長い時間に効く | 小 | なし（眠っていて動かない） |
| 2 | **時刻チェックとメニューバー更新を「次の予定まで寝る」形にする**（動いているタイマーなどがなければ長く寝る） | 毎秒 約 2.5 回減。常に効く | 小〜中 | なし |
| 3 | **窓の一覧の確認を 1 秒から 3 秒へ** | 回数は毎秒 0.7 回減。1 回が重い処理（数ミリ秒）なので、CPU への効きは回数以上 | 小 | 窓を閉じたときの反応が、最大 3 秒遅れる |
| 4 | **カーソル監視を粗くする**：近い 30ms を 60ms へ、遠い 150ms を 300ms へ | 毎秒 3〜16 回減 | 小 | 目で追うのが少しもたつく |
| 5 | **歩く動きを 30fps から 15fps へ**（歩幅は倍） | 歩いている間、毎秒 約 15 回減。一番大きいが、歩いている時間だけ | 中 | 動きがカクつく |
| 6 | **跳ね・まばたきのアニメーションを止める** | 毎秒 約 1 回と、描画プロセスの起床 | 小 | 静止画っぽくなる |
| 7 | **電源の状態の検出と、省電力モードの設定** | それ自体の効果はなし。4〜6 を電池のときだけに切り替える土台 | 中〜大 | 設定が増える |

進めるなら、次の順が効率的です。
1. **1 と 2**：見た目が変わらず、効果が確実です。電源に関係なく入れられます。
2. **3 と 4**：わずかな反応の遅れが出ますが、電源に関係なく入れても、気づきにくい範囲です。
3. **5 と 6**：見た目が変わるので、7（省電力モード）を作って、電池のときだけに切り替えるのがよいです。

## 省電力モードの案（未実装）

設定の「一般」に「省電力モード」を足す案でした。

- 選択肢：**自動**（バッテリー駆動のとき、または macOS の「低電力モード」のときだけ省電力）／**いつも省電力**／**オフ**。初期値は「自動」。
- 省電力のときに変える内容：
  1. 歩く動きを 15fps にして、歩幅を大きくする（速さは同じ）。
  2. 目的地での休みを長くする（今の 2〜6 秒を、8〜20 秒に）。
  3. 窓の上に飛び乗るのと、別の画面への遠出をやめる（窓の一覧の確認も 3 秒に 1 回）。
  4. カーソルを目で追うのをやめ、監視も 0.5 秒ごとにする。
  5. 眠るまでを 60 秒から 20 秒にして、眠っている間は計算を 500ms、カーソルの確認を 1 秒にする。
  6. 跳ねとまばたきのアニメーションを止める。
  7. 動いているタイマーがなければ、メニューバー更新などを 5 秒ごとに減らす。
- 効果の見込み（見積もり）：歩いている間、毎秒 50〜60 回の起床が 10 回前後に、眠っている間、20 回前後が 2〜3 回に。
- 代わりに、動きがカクつき、目で追わず、窓に乗らず、休む時間が長くなります。タイマーやリマインダー、ふきだしの知らせは、同じ精度で動きます。
- 電源の状態の見つけ方の候補：
  - バッテリー駆動かどうか：IOKit の `IOPSCopyPowerSourcesInfo`、または `pmset -g batt`（一定間隔で見る）。
  - 低電力モードか：`NSProcessInfo.isLowPowerModeEnabled`（`objc2-foundation` が使える）。変化の通知は `NSProcessInfoPowerStateDidChangeNotification`。

## 効果の測り方

実装するときは、前後を同じ方法で測って比べます。

- **起床の回数と CPU**：`top -l 3 -s 6 -pid <PID> -stats pid,command,cpu,idlew,power`。`idlew` は累計なので、サンプルの差を秒数で割ります。
- **CPU 使用率（配布版）**：`scripts/measure-cpu.sh <実行ファイル> [秒数]`（アプリ本体と WebContent の CPU 時間を測る。入力が 60 秒ないと眠って軽くなるので、最後の「入力が途切れていた秒数」も見る）。
- **サンプリング**：`sample <PID> 5 -file out.txt` で、どのスレッドが何をしているかを見る。
- **全体の電力**：アクティビティモニタの「消費電力（Energy Impact）」、または `sudo powermetrics --samplers tasks,cpu_power`。
- 測る状態を変える：歩いている最中、じっとしている最中、眠っている最中、ふきだしを出している最中。
